# Decisions

2026-10-03: One Android app module; API 26 minimum, installed stable API 36 compile/target. AGP 8.13.0 / Gradle 8.13 / Kotlin 2.2.20; Compose Material 3, OkHttp + kotlinx.serialization, Coil, Room and DataStore. App widgets use native RemoteViews. Browser OAuth reuses NextAuth with explicit approval and state/S256 PKCE exchange; credentials reuse the same bcrypt validation. Access JWTs last 10 minutes and are checked against revocable DB sessions; hashed refresh tokens rotate transactionally, replay revokes their session. Shopping/downloads/progress are account-local; shared recipes are online-only. Vision disabled by default, never silently substitutes fixtures. Stable installed tooling takes precedence over using the newest plugin.

2026-10-03 UI revision: Keep the chef-hat identity, cream/forest colors and Bricolage headings. Use Material 3 controls, compact outlined navigation, quiet missing-photo illustrations and one prominent cooking action. Instantiate the existing licensed variable font at weight 700 / optical size 28 rather than its weight-800 / optical-size-96 defaults. Preserve Kotlin/Compose; React Native and Expo skills inform mobile interaction principles without introducing another framework. The adaptive launcher icon reuses the existing hat within Android's safe area. App Store Connect work remains deferred until the user explicitly proceeds to iOS.

2026-10-03 Google revision: Explicit Google sign-in uses Android Credential Manager with a server-generated nonce and verified Google ID token. Register the debug Android package/certificate in the existing Google Cloud project and reuse its Web client as the token audience. The server returns the same revocable Recipe Buddy session as password sign-in. Browser/PKCE remains for account creation; no browser Google flow is launched by the native Google button. Registration details and production boundaries are in GOOGLE_SIGN_IN.md.

2026-10-03 second UI revision supersedes the first compact-art treatment: image-first square collection media, full original web category scenes, ingredient photography, shared photo source sheet and consistent 16 dp gutters. Friends now separates full-name chef rows from shared recipe media; invitation uses a compact branded rounded QR with decode checks and progressive disclosure of alternate methods.

2026-10-03 cooking revision: explicit widget configuration/pinning now authorizes a local owned-recipe instruction snapshot. Previous/Next modifies account-scoped Room progress without opening the app; only labelled header/Open app actions navigate. Sign-out/deletion revokes the snapshot. Voice Chef uses local technique coaching plus offline TTS, optional short on-device microphone commands and an original fictional roast personality. It does not invent cooking times/amounts or claim to inspect food; open-ended model conversation is not implemented.

2026-10-03 publication revision: Next 15 async request APIs, dependency security updates, stable sign-in age for deletion, versioned terms, reports/blocks, canonical EN/FR legal assets and maintenance endpoint. Production application, hosting retention, moderation operation, final upload signing and store submission remain explicit release work; see PUBLICATION.md.

2026-10-03 web parity revision: Native reviews, discussion, roasts and translations delegate to the existing web handlers, preserving validation, quotas, scoring and sharing rules. Accepted friendship does not expose a private collection: friend kitchens return only recipes actively shared with the caller. Native password account creation now replaces the earlier browser-only account creation entry. Recipe destinations bind to their own recipe ID, including back navigation. All seven badges and apron glyphs reuse the original web vectors. Printing is deliberately web-only after the user's explicit mobile removal request. The full inventory is in WEB_PARITY.md.
